### 非生产浏览器复验：手选、同版本刷新与版本冲突（详设 §4.4.1）

用独立测试事项、已认证非零环境用户、可见的两名候选：一人无有效报价基线或路由，一人有已知样本及参考价。浏览器网络面板只统计本事项的报价 POST 状态；不要保存令牌、请求正文或整份 HAR。每轮使用本轮自有资源，不确认承办，不在生产注入版本变化。

1. 打开事项，手选无价候选：显示不可报价而不是零文，确认按钮禁用。切换到有价候选，核对姓名、报价、确认按钮和数据库批次与所选人一致。
2. 读回同版本详情，保持该候选、原报价 ID 和确认状态；报价 POST 数不增加。点击“重新取价”才应产生新批次及新报价 ID，承办人不变。
3. 在隔离环境中让权威事项版本前进，保留当前页的旧观察版本。点击“重新取价”：报价请求返回 409；详情回读新版本后移除旧价，不能用旧价确认，不自动再次 POST。数据库无冲突请求的新批次，全程无扣款。

这是推荐/预算专题的页面复验，不替代上线后全局 FULL 或独立效果验收。记录实际使用的是完整应用还是独立挂载的原面板，以及哪些子组件、身份初始化或版本推进由夹具提供。实测批次统一记入[实施台账](tasks.md)。

### 非生产跨进程复验：把认证连续性与报价停收分开（详设 §7.1）

前置：固定同一候选 JAR，列出每个 API 进程、端口、调度节点标识及启动时的停收配置；共用隔离数据库、认证账号和业务夹具。只记录状态码、业务错误码、数据行数和公钥是否一致，不记录令牌、密码或报价正文。

1. 在开放进程用真实登录取得令牌并提交一批报价，保留该主体、事项版本、候选及幂等键。逐一向已停收进程提交原令牌和原输入。若返回 401，这是认证连续性失败，**不是**停收 503，也不证明原批次丢失。
2. 独立验证业务层：若节点不能互认令牌，在每个停收节点分别通过正常 PKCE 登录同一账号，核对 owner、环境与 client 相同。逐节点断言原键原输入返回相同完整批次；新键返回 503 `TASK_ASSIGNEE_ADMISSION_PAUSED` 且禁止缓存；原键改输入 409；读取他人事项 404。不得改签令牌、关闭鉴权或在 Web 重发新报价来使测试通过。
3. 比较前后数据库：只增加开放节点的原批次及其报价，不增加扣费或流水，不重新编码。两个进程各自通过不证明入口路由已摘除所有开放节点；按部署清单另核真实流量入口和原设备待传 ACK。跨节点保留原登录态的要求应由[认证模块](../account-security-foundation/design.md)验证，不能用重新登录标作会话连续。

## 旧实现验收合同（2026-11-07）

**本专题：单次模型推荐与用户显式确认承办。**

### 必须验证的业务结果
候选遗漏/重复/跨候选证据、事项变化409、无候选与无匹配不同、无害字段兼容、页面请求合并/迟到结果隔离；模型效果与静态Prompt测试分开。

### 不回归边界
不增规则评分/额外报价模型/业务自动重试/自动派单；旧候选子集不覆盖完整逐人评价；手选仍经原授权。

### 证据如何判定
- 绑定实际commit/tree、测试selector/fixture和输入；真实返回/数据库事实/页面行为只证明各自层，mock不冒充跨层验收。
- 必要身份/ACL、幂等、事务、锁及完整性保护按责任层覆盖；不在每个消费者复制同一防御矩阵。
- 性能使用真实同一请求/场景：请求数、查询数、读取字节、首字与完成时间分别记录；超标记录待优化，不用快速失败计成功。
- 以当前规则本地执行必要测试/构建并保存日志/制品摘要；本页历史Flow记录只证明当时输入，不要求重新付费Run。
- 源码接受、测试、安装、健康、业务验收分别写结果；不把历史PASS迁移到新tree，不补填未实测指标。
