### 同路由价目变动（§4.3、§6.1）

D339r 已验证原冻结研究不受库内调价影响；同一观察换用新价本时，调参误差仍为零并不能掩盖留出误差从 0 到 75%。在线判据（D340 已核范围见上）：原价可报价；同组部分费率改变时新请求不可借旧证据出价；既有报价原样回放；新价合格证据到位后仅新请求可恢复；不同组不连带停报。该组是否合格必须核整个合同，不仅读取样本中恰巧出现的价格。

### 预算覆盖与真值缺价（§6.1）

D338r 固定两条不同特征的训练事项，分别以含价 INPUT 与缺价 OUTPUT 计量；调参和留出各含两项可独立重算的真实成本夹具。仅选最近一项：两组均保留 2 项、仅 1 项可报价，有价项预测误差为零。换成留出事项本身缺价，必须以 `TOKEN_PRICE_MISSING` 中止，不生成有效报告。验证的是评估逻辑，不把夹具的 1/2 列为用户报价覆盖率。

### 推荐索引覆盖：计数相等不等于同一物理来源（§3.2）

D337r 在隔离 ES 将只读别名同时指向两代：① 同一授权 ID 各有一份、另一授权 ID 缺失，命中数恰等于期望数；② 129 人分两批，两批各自完整、各自仅一代，但批间代次不同。两者均不应进入编码或返回词法/向量排名，不应当成正常无匹配；完整授权名单仍可手选。正常单代、向量不全时的词法降级、读取期间 PIT 失效沿既有断言。组件负载测量不包含真实网关，不替代接口并发或排序效果验收。

### 盲标材料交接（§6.1）

在授权事实与完整名册冻结后、查看推荐结果前出表。以相反输入次序出表，应得到相同的候选呈现次序（来源字节摘要须各自绑定）；表中不出现内部 ID、划分、等级或推荐排序字段。保留空名册、资料不足和无合适人。独立填表后，整表核对且仅输出原评分器所需标签；遗漏、改动可见事实或错用另一来源摘要不得输出部分标签。D336 离线夹具已核导入、摘要错配及原评分结果；不代替真实样本的授权、正文脱敏核对、人工判断与独立留出成绩。

### 原设备清单不可跨安装借用（§7.1，D334）

固定同一主体、同一真实落盘来源和七份 ACK，在静态及动态托管安装各运行只读 CLI。完整条目且身份匹配时核对通过；仅改安装或仅改 host、缺安装或 host、只给旧清单片段均须非零退出且无盘点输出。身份正确而来源集合不符时仍应报告缺失/多余数，不能当作全部确认。指定 worker 的两种路径及相邻托管回归共 8/8；本批清单输入为夹具，不代表已逐设备分发真实 SQL 快照，不验证原实时会话仍有效。

D335r 补上生成器到正式消费者的联验：固定 `MeteredPeerMySqlTest` 中 `liveDiscussionDrainsEveryFrozenRevisionBeforeSessionRelease`（一份来源通过）、`registeredSecondDiscussionMissingFromDeviceCannotDrain`（已登记未落盘的第二来源必须阻止通过）、`fixedMultiTaskRosterSeparatesOriginalInstallationsAndRejectsRepinnedInputs`（两安装、拒绝变更）。前两项先冻结 SQL 名册和摘要，再投递、用正式 CLI 验私有完整条目、复取 SQL 核对同一摘要；不使用内部扫描函数代替 CLI。真实 MySQL 与文件、隔离 HTTP peer、测试身份和合成执行，没有生产会话或真实业务真值。

### 非生产浏览器复验：手选、同版本刷新与版本冲突（详设 §4.4.1）

用独立测试事项、已认证非零环境用户、可见的两名候选：一人无有效报价基线或路由，一人有已知样本及参考价。浏览器网络面板只统计本事项的报价 POST 状态；不要保存令牌、请求正文或整份 HAR。每轮使用本轮自有资源，不确认承办，不在生产注入版本变化。

1. 打开事项，手选无价候选：显示不可报价而不是零文，确认按钮禁用。切换到有价候选，核对姓名、报价、确认按钮和数据库批次与所选人一致。
2. 读回同版本详情，保持该候选、原报价 ID 和确认状态；报价 POST 数不增加。点击“重新取价”才应产生新批次及新报价 ID，承办人不变。
3. 在隔离环境中让权威事项版本前进，保留当前页的旧观察版本。点击“重新取价”：报价请求返回 409；详情回读新版本后移除旧价，不能用旧价确认，不自动再次 POST。数据库无冲突请求的新批次，全程无扣款。

这是推荐/预算专题的页面复验，不替代上线后全局 FULL 或独立效果验收。记录实际使用的是完整应用还是独立挂载的原面板，以及哪些子组件、身份初始化或版本推进由夹具提供。实测批次统一记入[实施台账](tasks.md)。

**补测在途改选，而非顺序点击。** 在移动宽度页面先选有参考价的 A，等回环网关实际收到编码请求后暂不应答。此时改选无报价路由的 B。分别检查：① 浏览器已取消 A 的报价请求，B 的请求未取消，确认按钮禁用；② 在放行网关前，独立证据显示两次 API 取价确实都在等编码，不用固定延时推测两请求已重叠；③ 放行后网关总入站仅一次，两人各有独立报价结果，页面持续显示 B 不可估算，即使 A 的批次已写入也不可拿 A 的价格确认 B。取消客户端等待不是撤销已受理的报价事务。应核对零资金流水/扣费，不要求数据库只能有后一条报价。此试验不采集线程栈正文或令牌作为回执，也不用于测 P95。

**补测在途改需求，而非仅提交过期版本。** 使用本轮自有的待承办事项、有效固定资料版本与原版本事前比较结果。先由授权用户为版本 V 独立取价；回环网关收到需求后暂不返回向量。用同一用户的另一请求通过正式 `requirements/edit` GET、PUT 修改需求描述（保留附件），按编辑键 GET 读回已提交的 V+1 和新需求修订。不要以测试直接 UPDATE 版本或固定延时替代这一步。此时原取价仍应在途，否则未验证编码不占编辑所需事项锁。

放行后，旧报价应为 409 `QUOTE_STALE`，不产生批次、可确认报价或扣费。显式按 V+1 重新取价时，网关输入应对应新需求；没有 V+1 的有效事前比较时不得沿用 V 的价格。同键回读已提交的新批次应完全一致且不再编码。只记状态、计数与版本，不记私有描述、向量或认证材料。

在 V+1 原批次无价时，先读未选状态，再为同一承办人显式固定首次交付方式。核对新比较凭据、意图摘要、私有测量绑定的需求修订及内容摘要；原选择键重放不得再次比较。证据齐备后分别验：原报价键仍返回原无价批次；显式新键可在有效基线与单价齐备时取得新价；重放新键不再编码。不自动重投、不执行任务、零账务。

### 切换清单：静态与动态托管设备主体（§7.1）

以实际启动参数固定 host 配置，静态主体与同 host 托管日志按权威主体键对账，静态别名去重，不能仅计静态配置行数。每个仅动态托管的主体也必须能由同一只读检查入口定位原 inbox，不能手工指定任意目录。分别验有原件及持久 ACK、少修订、未知主体、绑定冲突和来源缺失；拒绝时不初始化目录、不领取、不创建会话、不输出凭据。旧版工具不支持或候选漏掉一类主体，应记未验证并停止切换。空目录观测另与实际受理、执行及投递清单对账，不能自动视为排空。

### 非生产复验：独立报价的编码失败和恢复（详设 §4.4.1）

选择已授权、预计可报价的候选，使用从未编码过的需求文本。沿原 Web 取价、API、Chat 适配器发到隔离的回环网关。不打真实网关、不改模型配置。记录受测事项原批次与已解析报价数，并记录全库基线；估算历史中的旧报价不应清空，也不应算作本次新写入。

| 用户动作与网关返回 | 必须观察的结果 |
| --- | --- |
| 手选取价；网关返回 429 | 报价接口 503 `QUOTE_FEATURE_UNAVAILABLE`，保留人选，无报价；无人操作时不再次外发。 |
| 显式重试；网关 HTTP 200，但返回错误维数，再显式重试返回错误模型身份 | 两次均为 502 `QUOTE_FEATURE_INVALID`，不得给零文或“候选无能力”。每次操作只有一次编码；每个失败观察点都未增批次、报价或账务。 |
| 同一意图再次显式重试；网关返回正确模型的有效向量 | 请求标识和幂等键保持原值，成功价绑定原人选；仅此时新增一批一价，不扣款。不重新调用推荐。 |

计数同时从 Web 报价 POST、网关实际入站次数、数据库差量核对，不把重新渲染、失败重试或历史样本计成新意图。此用例不证明真实网关可用率、延迟或估价准确率。

### 非生产跨进程复验：把认证连续性与报价停收分开（详设 §7.1）

前置：固定同一候选 JAR，列出每个 API 进程、端口、调度节点标识及启动时的停收配置；共用隔离数据库、认证账号和业务夹具。只记录状态码、业务错误码、数据行数和公钥是否一致，不记录令牌、密码或报价正文。

1. 在开放进程用真实登录取得令牌并提交一批报价，保留该主体、事项版本、候选及幂等键。逐一向已停收进程提交原令牌和原输入。若返回 401，这是认证连续性失败，**不是**停收 503，也不证明原批次丢失。
2. 独立验证业务层：若节点不能互认令牌，在每个停收节点分别通过正常 PKCE 登录同一账号，核对 owner、环境与 client 相同。逐节点断言原键原输入返回相同完整批次；新键返回 503 `TASK_ASSIGNEE_ADMISSION_PAUSED` 且禁止缓存；原键改输入 409；读取他人事项 404。不得改签令牌、关闭鉴权或在 Web 重发新报价来使测试通过。
3. 比较前后数据库：只增加开放节点的原批次及其报价，不增加扣费或流水，不重新编码。两个进程各自通过不证明入口路由已摘除所有开放节点；按部署清单另核真实流量入口和原设备待传 ACK。跨节点保留原登录态的要求应由[认证模块](../account-security-foundation/design.md)验证，不能用重新登录标作会话连续。

**补验原设备仍在比较时的停收窗口。** 同一固定三端候选并行开放与停收两个 API 节点，同一业务主体各自正常登录。开放节点已提交首次选择、原设备拿到比较请求但尚未回传时，在停收端分别验原无价批次重放、已选方式与只读推荐可读、新报价/选择拒绝；核无额外批次或探测。再放行原设备，核同一会话、票据、意图和测量；旧价不得变化，只有用户显式向仍开放的验证节点取价才能产生新批次，该批次可在停收端重放。不得以比较回复冒充执行用量持久回执，也不得以此双节点实验冒充实际入口均已暂停。

**补验逐修订投递而非配置比较。** 固定同一已签发设备会话及该派发的历史执行授权、冻结成员和上下文，由同一设备投递进程发送。开放接收节点已持久确认前四份时，核设备四份回执；在另一已停收节点证明新业务键返回 503，再将剩余修订投递至该节点。在 RESPONSE 服务端提交后丢弃其回复，必须以原 receiptId 取回原回执，余下终态修订照常确认。将每个已提交 ACK 的完整业务字段分别与原设备文件和数据库逐一比对；另核一份 RESPONSE 只产生一条账本修订，缺真实用量仍为未知成本。不要用总数相等、重新登录的设备、配置探测回复或业务报价代替上述检查。

**旧节点如何计入清单。** 在获授权的切换窗口重新核对入口配置、实际监听进程、其打开的安装 JAR 与安装回执。不能因候选包已实现暂停，就假设旧包也识别同一配置。旧节点未证明具备业务停收能力时，先从受影响写入流量中摘除，或先发布只增加停收能力的兼容版本；有未覆盖的入口就不进入下一阶段。普通代理按路径/方法拦截无法区分同一 POST 的新意图与原键重放，不能据此勾选“旧回执仍可读”。摘流后的回执读取、原设备上报与 ACK 收尾需各自实证。不要屏蔽整个 `/agent` 或所有 `/quotes`：同一前缀还有与本次无关的接口。

## 旧实现验收合同（2026-11-07）

**本专题：单次模型推荐与用户显式确认承办。**

### 必须验证的业务结果
候选遗漏/重复/跨候选证据、事项变化409、无候选与无匹配不同、无害字段兼容、页面请求合并/迟到结果隔离；模型效果与静态Prompt测试分开。

### 不回归边界
不增规则评分/额外报价模型/业务自动重试/自动派单；旧候选子集不覆盖完整逐人评价；手选仍经原授权。

### 证据如何判定
- 绑定实际commit/tree、测试selector/fixture和输入；真实返回/数据库事实/页面行为只证明各自层，mock不冒充跨层验收。
- 必要身份/ACL、幂等、事务、锁及完整性保护按责任层覆盖；不在每个消费者复制同一防御矩阵。
- 性能使用真实同一请求/场景：请求数、查询数、读取字节、首字与完成时间分别记录；超标记录待优化，不用快速失败计成功。
- 以当前规则本地执行必要测试/构建并保存日志/制品摘要；本页历史Flow记录只证明当时输入，不要求重新付费Run。
- 源码接受、测试、安装、健康、业务验收分别写结果；不把历史PASS迁移到新tree，不补填未实测指标。
